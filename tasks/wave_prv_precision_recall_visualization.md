# Wave PRV — визуальное объяснение improved precision/recall@k

**Статус:** к реализации.  
**Тип:** объяснительная визуализация; не новый подтверждающий эксперимент.  
**Связь с мастер-планом:** §2.3 (локально-геометрические метрики), §5 (синтетическая
калибровка направлений) и §6 (интерпретация направленных контрастов).

## Цель

Добавить воспроизводимые 2D-иллюстрации того, как improved precision/recall@k
классифицирует точки. Рисунки должны объяснять направленность метрик:

- для `precision@k` локальные окрестности строятся вокруг точек референса `P`;
  оцениваются точки модели `Q`;
- для `recall@k` локальные окрестности строятся вокруг точек `Q`; оцениваются
  точки `P`.

Визуализация не изменяет реализацию метрик, результаты S0–S4/C0–C4/LLM, пороги,
pre-registration или выводы. Она должна быть маркирована как иллюстрация механики,
а не как дополнительное статистическое доказательство.

## Математическая конвенция

Для облака центров `X = {x_i}` и целого `k >= 1` положить

`r_i^(k) = расстояние от x_i до k-го ближайшего *другого* элемента X`.

Тогда его kNN-manifold — объединение замкнутых дисков

`M_X^(k) = union_i B(x_i, r_i^(k))`.

При `P` = reference и `Q` = model:

- `precision@k = mean_j[ q_j принадлежит M_P^(k) ]`;
- `recall@k = mean_i[ p_i принадлежит M_Q^(k) ]`.

Точка на границе считается покрытой (допуск `atol=1e-12`). При непрерывных
синтетических координатах равенства расстояний практически отсутствуют. Если для
визуализации нужен детерминированный выбор выделенной точки/соседа, его индекс
должен быть записан в конфигурации, а не выбран после просмотра картинки.

## Объём реализации

### 1. Новый модуль

Добавить `src/tda_metrics/precision_recall_viz.py` с публичными функциями:

- `knn_radii(points, k) -> np.ndarray` — радиус каждой точки, исключая саму
  точку; валидация: двумерный массив, `1 <= k < len(points)`.
- `coverage_mask(centers, radii, query, atol=1e-12) -> np.ndarray[bool]` —
  принадлежность каждой query-точки объединению дисков центров.
- `precision_recall_membership(P, Q, k, atol=1e-12) -> dict` — радиусы,
  маски и скалярные `precision`, `recall`; значения должны быть рассчитаны из
  тех же масок, которые рисуются.
- `plot_precision_recall_panel(...)` — одна панель одного направления.

Не дублировать или заменять `TopologyMetrics.improved_precision_recall`.
Модуль нужен только для прозрачной 2D-геометрии и не должен импортировать
TensorFlow, MTD или RTD.

### 2. Детерминированные сценарии

Использовать только нативную 2D-синтетику из `tda_metrics.mixtures`:

- `same_law`: независимые `P` и `Q` из восьмимодового референса;
- `mode_drop`: `Q` с симметрично удалённой парой мод;
- `mode_invent`: `Q`, где фиксированная доля точек заменена симметричной парой
  внешних мод.

Для последних двух сценариев нельзя использовать существующий
`sample_q_dropping_invention`, если он не гарантирует одновременно симметрию
среднего и буквально заданную долю заменённых точек. Для иллюстрации допустим
небольшой локальный детерминированный sampler с явным полем `replaced_fraction`
в манифесте. Он не является новой серией S3 и не должен подменять её результаты.

Основная фигура использует `k=3`, одинаковое число точек в трёх строках,
фиксированные seed’ы и одинаковые оси во всех шести панелях.

### 3. Фигуры

Записать PNG в `results/figures/`:

1. `prv_precision_recall_semantics.png` — сетка 3x2.
   Строки: same-law, mode drop, mode invention. Столбцы: precision и recall.
2. `prv_precision_recall_k_sweep.png` — влияние `k={1,3,10}` на одном заранее
   заданном mode-invention сценарии: одинаковые оси, одна и та же пара облаков.

Для каждой панели обязательно:

- полупрозрачные диски соответствующего облака и тонкие границы дисков;
- центры облака, по которому строится manifold;
- оцениваемые точки: зелёный = покрыта, красный = не покрыта;
- ровно одна заранее заданная выделенная центральная точка, её k-й сосед,
  отрезок до него и подпись `r_i^(k)`;
- заголовок с направлением и значением, например
  `precision@3 = 0.840 (Q in M_P)`;
- легенда, подпись о том, какое облако задаёт радиусы, и единый масштаб осей.

Не рисовать окружности в PCA-2-проекциях CLIP, CIFAR или LLM как будто они
являются рабочими окрестностями PCA-16/512/2048. При желании позже допускается
отдельная PCA-2-иллюстрация, но только с явной подписью
«проекция; метрика здесь не вычислялась».

### 4. Артефакты и оркестрация

Добавить лёгкий CPU-раннер `scripts/run_precision_recall_visualization.py`.
Он должен:

- принимать `--out-dir` (по умолчанию `results/raw/prv`) и `--fig-dir`
  (по умолчанию `results/figures`);
- создавать результат атомарно и не перезаписывать существующий запуск при
  несовпадающей конфигурации;
- записывать `manifest.json`, `summary.json` и `memberships.csv`;
- сохранять seeds, `k`, размеры облаков, координатный sampler, SHA-256
  конфигурации, версии Python/numpy/scipy/matplotlib и статус;
- продолжать независимые сценарии после ошибки и завершаться ненулевым кодом,
  если не построена хотя бы одна обязательная фигура;
- не требовать GPU или тяжёлый стек.

`memberships.csv` должен содержать минимум `scenario`, `direction`, `k`,
`point_role`, `point_index`, `x`, `y`, `covered`, `radius` (radius только для
центров) и позволит проверить любое цветовое решение на фигуре.

### 5. Проверки

Добавить `tests/test_precision_recall_viz.py` без тяжёлых зависимостей.
Минимальные тесты:

1. `knn_radii` исключает саму точку и отвергает недопустимый `k`;
2. `coverage_mask` правильно обрабатывает попадание, промах и границу;
3. `precision_recall_membership` даёт ожидаемые precision/recall на маленьком
   вручную заданном примере;
4. зеркальность: precision `(P,Q)` совпадает с recall `(Q,P)`;
5. для случайных 2D-облаков без ties значения helper’а совпадают с
   `precision_recall.knn_precision_recall_features` для `k={1,3,10}` в
   Colab/heavy-среде. Этот тест можно маркировать skip, если внешняя библиотека
   не установлена, но CPU-тесты обязаны проходить всегда;
6. smoke-тест раннера во временной директории создаёт два PNG, валидный manifest
   и строки всех трёх сценариев.

## Критерии приёмки

Задача готова, когда выполнены все пункты:

- `pytest tests/test_precision_recall_viz.py -q` проходит в лёгком окружении;
- CPU-раннер создаёт оба PNG и raw-артефакты с `status: ok`;
- в heavy-среде зафиксирован parity-check с production-библиотекой;
- значения в заголовках равны среднему нарисованных mask’ов, что проверено
  автоматически;
- фигуры открываются, все панели имеют одинаковые лимиты осей в рамках фигуры,
  текст читаем и нет обрезанных легенд;
- нет изменений в `report/coursework.md`, существующих `results/raw/*`,
  `TopologyMetrics` или числовых выводах исследования.
