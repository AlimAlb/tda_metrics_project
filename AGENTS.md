# AGENTS.md

Контекст для агентов, работающих с этим репозиторием.

## Проект

Курсовая работа: сравнение метрик схожести двух облаков точек (P = «данные», Q = «модель») — топологические (MTD, RTD), improved precision/recall, статистические (MMD, Fréchet-формула FID, JS-дивергенция). Проверка корреляций между метриками на синтетике (кольцо / диск / раздвигающаяся смесь с деформацией) и на CLIP-эмбеддингах реальных данных (MNIST, Fashion-MNIST, CIFAR-10-C). Язык артефактов — русский. В рабочих файлах не использовать обращение «научрук» — только «научный руководитель» / «из переписки».

## Свойства метрик (проверено экспериментально на T4)

- **MTD**: асимметрична (считать оба направления); скор = сумма длин H1-баров; значения при разных `batch_size` несравнимы — обертка всегда берет полные облака; H0/H1-разложение — `mtd_homology`; шумовой пол H1 низкий (~5.6 при n=900 на «том же законе»)
- **RTD**: симметрична; требует `|P| == |Q|`; инвариантна к сдвигам (матрица строится только из внутренних расстояний облаков); **высокий шумовой пол** (~35 при n=900, ~52 при n=1500 на «том же законе») — сравнивать только при равном n и с контролем
- **improved PR**: один вызов возвращает сразу precision и recall; TF1-совместимость включается в `metrics.py` до импорта `precision_recall`; `allow_soft_placement` для CPU; `reset_default_graph` после каждого вызова
- **NTD** (Dmitriev et al., IEEE Access 2025; статья — `docs/ntd_paper.pdf`, суть и формула — в §11 ноутбука): `ntd(X, Y)` = кросс-расходимость mtd⁰ / шумовой пол референса; **X — «модель», Y — «данные»**; ≈1 — один закон, <1 — модель «внутри» данных (precision-подобно), >1 — моды вне данных; обратное направление — про покрытие (recall-подобно); в `compute_all` — `ntd_PQ` (данные→модель, recall-подобно) и `ntd_QP` (precision-подобно); стоит ~1-2 с, сравнима между экспериментами и пространствами — в отличие от MTD/RTD; `mtd0(P,Q)·|P| == mtd_homology(P,Q)['H0']` (кросс-чек с ripser++ тестом, rel=1e-4). Ключевые числа: mode-invention MNIST — precision-направление 1.52→1.01 по классам (Fig. 5 статьи воспроизведена); круг/дуга: 2.11 vs контроль 1.42 в пикселях-16, 1.77 vs 1.33 в CLIP-16
- **Стоимость `compute_all`** (1000+1000 точек): RTD ≈ 17 c (5 усреднений) — узкое место; MTD ≈ 3 c; PR ≈ 1.2 c; статистические ≈ 0.1 c
- Fréchet не видит раздвигание смеси с сохранением моментов; на 512-мерных CLIP-эмбеддингах improved PR почти слеп (precision@10 ~ 0.003) — **PCA-16 ремонтирует** (0.34; на CIFAR-деградации → 1.00), внутренний оптимум d≈16
- **CLIP/DINO инвариантны к повороту MNIST-цифр** — цикл вращения невидим топологическим метрикам через эти эмбеддеры (контроль «круг vs круг» = «круг vs дуга»); в VAE-латенте RTD видит (41 vs 28); на CIFAR-поворотах CLIP реагирует остро — слепота домен-специфична, свойство эмбеддера, не метрики
- JS деградирует при малых n×d: 0 при 900×16 CLIP, работает при 1500×16 и в VAE-латенте — оговаривать

## Грабли (проверено на GPU)

- `pip install -e` невидим для уже запущенного ядра (`.pth` читается только при старте интерпретатора) → ставить обычным `pip install ./dir`
- numpy 2.x: `np.random.set_state` (метода `restore_state` не существует)
- JS в высоких размерностях: считать сразу `log_ball_volume = 0.5*d*log(pi) - gammaln(d/2+1)`; через exp→log ловится underflow при d=512
- Файлы на `/mnt/c` имеют права 0777 — ssh-ключи использовать только через копию в `~/.ssh` (chmod 600)
- На VM эмбеддинги кэшируются в `embeddings/`, датасеты в `data/` — повторные прогоны дешевле (но кэш умирает вместе с сессией)
- **Сессии Colab репаются**: IDLE-сессия живёт минуты; разрыв локального туннеля (убитый nohup-процесс) ускоряет смерть даже BUSY-ядра. Результаты забирать из логов немедленно; длинные цепочки — единым мега-скриптом kernel-side (setup+секции в одной ячейке, секции в try/except)
- **Убитый/зависший exec клинит ZMQ-канал ядра**: последующие exec уходят в никуда (ядро IDLE, клиент ждёт). Лечится `colab restart-kernel`, не пересозданием сессии. Вывод длинных прогонов дублировать в файл на VM (`Tee` в stdout) и забирать `colab download`
- **MTopDiv с dim=0 висит в exec-контексте** (связка ripser++ `--dim 0` + `pairwise_distances(n_jobs=40)` в цикле — 16+ мин на одном вызове). Поэтому `mtd0` реализован напрямую: H0-баркод = merge-дистанции single-linkage → `scipy.cluster.hierarchy.linkage`, ~миллисекунды

## Colab CLI (валидация на GPU)

- `colab` 0.6.0 (pipx) + **обязательно** injected `jupyter-kernel-client` из `git+https://github.com/googlecolab/jupyter-kernel-client.git` — версия с PyPI несовместима (`no attribute KernelClient`); inject привязан к имени venv `google-colab-cli` и может пропадать при обновлениях — проверять `.../venvs/google-colab-cli/lib/python3.*/site-packages/`
- Все команды — с `--auth=oauth2` (токен в `~/.config/colab-cli/token.json`)
- Сессия = VM + живое ядро с общим состоянием (как ноутбук); `colab new --gpu T4` / `colab stop`; после stop всё на VM теряется
- Длинные прогоны — **только фоном** с логом и периодическим опросом:
  `nohup colab --auth=oauth2 exec -f script.py --timeout 1800 > /tmp/opencode/colab_run.log 2>&1 &`
  запуск — отдельным вызовом bash-инструмента (хвостовые команды в том же вызове заставляют шелл ждать фонового ребёнка и таймаут убивает всё); опрос — отдельными вызовами
- `colab exec -f nb.ipynb` пишет executed-копию `*_output.ipynb`; `--timeout` — на ячейку, дефолт 30 с — всегда увеличивать
- **`colab exec` возвращает rc=0 даже при ошибке ядра** — проверять лог, не код возврата
- **`SystemExit` в exec-скриптах вешает ядро** (IPython ловит интерактивно) — никогда не поднимать, только print и естественное завершение
- `colab upload` — remote_path только абсолютный (`/content/...`), относительные молча теряются
- В exec-скриптах «голое» выражение в конце ячейки не печатается — только `display()`/`print()` (в ноутбуке хвосты рендерятся нормально)
- Валидация пакета: zip (`src`, `tests`, `pyproject.toml`) → `colab upload` → `pip install` → `pytest` → smoke `compute_all`; «боевой» путь (git clone репозитория → install) проверен
- Запуск непушенного кода в полном прогоне: `/content/tda_metrics_repo` распаковать из zip до прогона — ячейка §0 (`git clone || echo`) пропустит клон и `pip install ./tda_metrics_repo` поставит локальную версию
- Полный прогон ноутбука: ~50 мин на VM с горячими кэшами эмбеддингов, 2–4 ч с холодными (CIFAR-10 170 МБ иногда качается по 150 кБ/с ≈ 19 мин; в другой раз — 200+ МБ/с); `--timeout` — на ячейку; артефакт `*_output.ipynb` пишется рядом с исходным; после DONE забирать сразу — IDLE-сессия умирает через минуты
